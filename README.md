# pbc-checker-ccx

Проверка PBC-невязок для CalculiX: инструмент читает связи `*EQUATION` из `.inp`
и перемещения (блоки `DISP`) из `.frd`, считает для каждого уравнения невязку
`r = Σ aᵢ·u(узелᵢ, dofᵢ)` и выносит вердикт PASS / FAIL / N/A с отчётом.

Ниша свободна (скан 2026-10-06): GCI/MMS-инструменты существуют, отдельного
PBC-чекера для CalculiX нет — pycalculix и calculix-frdconvert только парсят .frd.

## Зачем

Гейт «PBC-невязки» стадии FE-эталона. Боевые наблюдения
(2026-09): чистые прогоны дают ≤3·10⁻⁹, испорченные — 20…2·10³ при том же
.inp. Инструмент — дискриминатор таких прогонов: ворота между «формат файла» и «решение
развалилось».

## Точность — честно

ASCII .frd хранит перемещения в формате E12.5 (6 значащих цифр). Значит
сертифицируемый уровень невязки ≈ 5·10⁻⁶·max|u| — всё ниже этого пола неотличимо
от шума формата. Пол оценивается автоматически и печатается в отчёте. Порог
по умолчанию 10⁻³ относительной невязки — на три порядка выше пола и на четыре
ниже испорченных прогонов; меняется флагом `--tol`.

## Установка и запуск

```bash
pip install -e .          # нужен pip >= 21.3 (PEP 660); зависимость: numpy
pbc-check job.inp                         # .frd = job.frd
pbc-check job.inp --frd job.frd --tol 1e-4 --out-dir docs/audit_trace_2026-10-06
```

Коды выхода: `0` PASS/N/A, `1` FAIL, `2` любая ошибка (нет .frd / нет DISP / битые
уравнения / узел без DISP / бинарный .frd / неожиданный сбой — crash не маскируется
под FAIL). При FAIL в консоль печатается текст худшего уравнения (не только индекс) —
виновник виден и без отчёта. Кириллица и «ёлочки» в сообщениях не роняют прогон
при редиректе в файл с чужой кодировкой (cp1252 в CI) — символы заменяются.
Отчёты `pbc_report_<job>_<дата>.{json,md}` пишутся при `--out-dir` для любого
вердикта, включая N/A (audit_trace без дыр), и содержат: дату UTC, sha256 обоих
файлов, версию ccx из заголовка .frd, таблицу по шагам, топ-10 худших уравнений
по относительной невязке; повторные прогоны дописывают отчёт с суффиксом времени,
а не перезаписывают (append-only).

Пример: `python examples/make_example.py`

## API (для интеграции)

```python
from pbcchecker import check_job
v = check_job("job.inp", "job.frd", tol=1e-3, out_dir="docs/audit_trace_2026-10-06")
v.verdict       # "PASS" | "FAIL" | "N/A" (в deck нет *EQUATION)
v.passed        # True | False | None
v.max_rel_residual
```

## Интеграция во внешний пайплайн — по умолчанию ВЫКЛЮЧЕНО

Инструмент внешний, в расчётный путь не входит. Включается явно,
когда нужен гейт:

```yaml
# experiment_config.yaml (новый опциональный ключ; отсутствие = выключено)
pbc_check:
  enabled: false
  tol_rel: 1.0e-3
  out_dir: docs   # отчёты лягут в audit_trace папку дня
```

```python
# в точке после ccx-прогона (пример), guard дешевле импорта:
cfg = config.get("pbc_check", {})
if cfg.get("enabled"):                       # default off
    from pbcchecker import check_job         # импорт только при включённом флаге
    v = check_job(inp_path, tol=cfg.get("tol_rel", 1e-3),
                  out_dir=audit_trace_dir)
    if v.verdict == "FAIL":
        raise RuntimeError(f"PBC-невязка {v.max_rel_residual:.3e} — прогон забракован")
```

`N/A` (нет `*EQUATION` — не-периодический прогон) считается пройденным.

## Форматы (проверены на боевых файлах ccx 2.20)

- `*EQUATION`: строка-карточка, следующая строка — число термов N, далее 3N значений
  «узел, dof, коэф.» с произвольными переносами строк; поддерживается метод управляющих
  узлов (ghost-узел первым). Коэффициенты
  — обычный float, фортран-экспоненты без «E» (`1.0-100`) и с «D» (`1.0D+00`) тоже;
  висячие/двойные запятые и лишние значения после 3N диагностируются (лишние — ошибка).
  Оборванное уравнение (следующая `*`-карточка до набора 3N значений) — ошибка
  с номером строки, а не тихо съеденные термы. `*INCLUDE` раскрывается рекурсивно
  (пути относительно включающего файла, защита от циклов) — PBC в отдельном файле
  проверяются, а не дают молчаливое N/A. Кодировка utf-8-sig: BOM и cp1251-комментарии
  не ломают разбор.
- `.frd` ASCII (ccx ≥ 2.8): блок ` -4  DISP …` … ` -3`; строка узла ` -1`, номер I10,
  значения 3×E12.5 фиксированной ширины; при слипшихся полях — откат на split().
  Блоки `DISPI` (мнимые перемещения частотных задач) пропускаются; многошаговые файлы
  (шесть единичных деформаций + моды) обрабатываются целиком, вердикт по худшему шагу.
  Битая структура (незакрытый `-3`, пустой блок, нечитаемая строка узла) — ошибка
  с номером строки; узел уравнения без записи DISP — ошибка данных, не WARN;
  бинарный .frd/.fil детектируется и даёт отдельное сообщение.
- Поддержаны только поступательные DOF 1–3 (твёрдое тело); dof вне 1–3 — ошибка данных.

## Модули

| Модуль | Ответственность |
|--------|-----------------|
| `inp_equations` | разбор `*EQUATION` (продолжения строк, комментарии `**`, ошибки с номером строки) |
| `frd_disp` | потоковое чтение блоков `DISP` (O(узлов) памяти), версия ccx из заголовка |
| `residual` | векторная невязка (`np.add.reduceat`), нормировка max\|u\|, пол чувствительности |
| `report` | JSON+Markdown, sha256, датирование, топ худших уравнений |
| `gate` / `cli` | API `check_job` и CLI с кодами выхода |

## Производительность

Бенчмарк: `python tools/bench.py` (100k узлов, 40k уравнений, 5 шагов, ~500k
строк узлов в .frd). Относительно первой версии (1.35 c end-to-end):
- разбор .frd **3.5×** (0.99 → ~0.3 с): стандартные строки узлов ccx имеют
  фиксированную ширину 50 (« -1» + I10 + 3×E12.5) — однородный блок парсится
  векторно как uint8-матрица (цифры → числа матричной арифметикой), без
  питоновского цикла по строкам; нестандартные блоки — построчный fallback;
- `check_job` без `--out-dir` **2.3×**: sha256 и рендер всех уравнений
  считаются только когда нужен отчёт.
Точность: векторный разбор побитово равен `float()` (точная ldexp-схема для
экспонент k in [-22, 13]; вне диапазона блок автоматически уходит в построчный
разбор — корректность важнее скорости). Регрессионная защита — тесты
`torture_bitwise`/`glued_fields_bitwise` и мутационное тестирование.

## Тесты

84 pytest-теста: 76 юнит- (разбор .inp: оборванные уравнения, n_terms<1, BOM, cp1251,
фортран-экспоненты, висячие запятые, лишние значения, *INCLUDE с циклами, вложенностью
и границей глубины 32; .frd: DISPI, fallback, битая структура, бинарный файл, 10-значные
узлы, номера строк в ошибках, побитовая точность векторного парсера — слипшиеся поля,
границы ldexp-схемы, пытка разрядами; PASS/FAIL/N/A, многошаговость, граница порога
«ровно = tol», пол чувствительности 5e-6·max|u|, отсутствующие узлы, коды выхода CLI,
`--tol`, append-only отчёты) и 8 e2e (subprocess: потоки PASS/FAIL/N/A, редирект с чужой
кодировкой, кириллические пути и другой cwd, BOM+*INCLUDE, deck на 750 уравнений × 3 шага).
Покрытие строк 99% (непокрытое — `if __name__` и защитный except).

```bash
python -m pytest -q                 # всё
python -m pytest -q -m "not e2e"    # только быстрые юниты
```

Мутационное тестирование (свой движок, mutmut на Windows не работает):

```bash
python tools/mutate.py              # ~260 мутантов; выжившие -> tools/mutants_survived.txt
```

Счёт: cli/gate/report 100% убито, residual/inp_equations 97%, frd_disp 60% —
но в frd_disp числовое ядро векторного парсера убито на 100% (тесты
`torture_bitwise`/`glued_fields_bitwise` побитово); остальные выжившие —
«самолечение»: мутация валидации уводит блок в построчный fallback с тем же
результатом (список с обоснованиями — в docstring tools/mutate.py).
